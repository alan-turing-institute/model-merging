# PR title

Fix -inf/NaN KD loss from underflow in normalize_logprobs

# Description

`normalize_logprobs` (`src/axolotl/integrations/kd/utils.py`) renormalized top-k logprobs by converting them to probabilities and back (`exp`, divide by the sum, `log`). In fp32, `exp()` underflows to exactly 0 for any entry more than about 103 nats below the row's maximum, so that entry came back as `log(0) = -inf`.

This PR renormalizes in log space instead:

```python
return logprobs - torch.logsumexp(logprobs, dim=-1, keepdim=True)
```

This is mathematically identical and equals `log_softmax` over the top-k. The old divide-by-sum step did nothing, because the values already summed to 1 after the logsumexp shift. The -inf padding to `topk` is unchanged. The function's two callers, the student side of the Liger top-k KL loss (with `kd_normalize_topk`) and `collator_online_teacher`, get the same values except at the extremes, where they now stay finite.

It also adds `tests/integrations/kd/test_normalize_logprobs.py`, with four tests:

- the result matches `log_softmax`, including the -inf padding path;
- an entry 120 nats below the max stays finite;
- end to end, `LigerFusedLinearKLTopKLogprobLoss(normalize_topk=True)` gives a finite loss and finite gradients when a teacher top-k token has a student logit about 200 below the others.

## Motivation and Context

Fixes #<ISSUE_NUMBER>

I'm using Axolotl's KD plugin for offline self-distillation of `google/gemma-3-4b-it` on XSum summarization, with top-20 teacher logprobs generated by vLLM. Training runs that put the reference summary in the assistant turn diverged during warm-up: `grad_norm` became NaN at step 7 or 8, every later eval loss was NaN, and the trained model output empty strings. Changing the learning rate and seed didn't help, and every run showed `eval_loss: inf` at step 0.

Tracing it: after an apostrophe, the student is almost certain of the next token (`s`), but the teacher's top 20 still includes tokens like `▁Trading` at about -25 that the student puts at about -115. The student-side `normalize_logprobs` turns those into `-inf`, so the forward KL is `inf`, and the backward pass through `log(exp(x))` gives `inf * 0 = NaN`. With the base model's weights, 2 of 1,000 eval samples and 7 of the first 3,500 training samples in my data hit this.

## How has this been tested?

Run locally on Linux (CPU for the unit tests), Python 3.12.14, torch 2.11.0+cu130:

- `pytest tests/integrations/kd/test_normalize_logprobs.py tests/integrations/kd/test_liger_loss.py tests/integrations/kd/test_topk_forward_kl.py`: 14 passed.
- With the old `normalize_logprobs` and the new tests: the two underflow tests fail (non-finite result and `inf` loss) and the two equivalence tests pass. So the tests catch the bug, and the fix changes nothing in the normal range.
- `ruff@0.15.8 check` and `ruff@0.15.8 format --check` on both changed files: clean.
- On my real data (gemma-3-4b-it base weights, GH200), I ran each of 1,000 tokenized eval samples through `LigerFusedLinearKLTopKLogprobLoss` (forward and backward). With 0.18.0's `normalize_logprobs`, 2 samples gave an `inf` loss and NaN gradients. With this change, all 1,000 samples of a second variant of the same eval set are finite: same teacher logprobs, different student prompt, and a worst student top-k gap of 116 nats. I didn't keep the first variant, so I couldn't re-run that exact set.
