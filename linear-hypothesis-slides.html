Model Merging Investigation · Replication Note

Is Task Arithmetic Uniquely Special?

A recent systematic study, "A Systematic Study of In-the-Wild Model Merging for Large Language Models" (arXiv 2511.21437v2), claims that of six merge methods tested on in-the-wild heterogeneous fine-tunes, Task Arithmetic is the one that reliably beats the base model — reaching 100% success once enough checkpoints are merged. We replicated their regime on their own Qwen3-4B and found a simpler explanation for why Task Arithmetic looks special.

Dr Justin McInroy & Dr Mariusz Pietrzyk · TIRE · The Alan Turing Institute

Setup

Replicating the paper's exact regime

Qwen/Qwen3-4B + 7 independently-sourced community fine-tunes with genuinely different training objectives — agentic tool-use, uncensoring, formal theorem-proving, Russian instruction-tuning, Chinese grammar correction, multilingual moral reasoning, behavior simulation. n=7, above the paper's reported n≥6 threshold for "in-the-wild" success.

  • What "n" means: the number of fine-tuned checkpoints merged into one model. The paper tests n ∈ {2, 4, 6, 8, 10, 12} on each base model, sampling 15 combinations per n, and reports how "success" scales with n — e.g. for their own Qwen3-4B, Task Arithmetic's success rate goes 47% (n=2) → 80% (n=4) → 100% (n=6, n=12). We ran one combination at n=7, past their n≥6 threshold.
  • 5 merge methods tested: Linear, TIES, DARE-TIES, Task Arithmetic, Arcee Fusion — all at matched, equal weighting (1/7 per checkpoint, or the 2-way equivalent).
  • 2 benchmarks: ARC-Easy (2,376 items) and PIQA (1,838 items), scored per-item for paired McNemar's exact tests and a clustered GEE.
  • Success criterion (paper's own, confirmed against their text): does the merged model beat the base model — not "beats every source checkpoint," a different, stricter metric the paper reports separately (their Table 2). We checked both; the qualitative pattern is the same either way, so we report the paper's actual metric here.

Follow-up — retuned to the paper's hyperparameters

The collapse was a hyperparameter artifact, not a method failure

Same 7 checkpoints, same base model, only the TIES/DARE-TIES settings changed: density 50% → 10% (top-10% magnitude threshold, matching the paper), weight 1/7 → 0.1 unnormalized (matching their λ=0.1 scaling).

With this fix, all five methods tested now succeed on Qwen3-4B at n=7, not just Task Arithmetic and Linear — which pushes back further on the paper's "most methods fail in the wild" framing than we first thought.

The linear hypothesis

At matched weights, the two formulas are algebraically identical

Task Arithmetic and Linear look conceptually different — one edits relative to a base model, the other averages checkpoints directly. But when weights sum to 1, they collapse to the same computation:

Task Arithmetic:  merged = base + Σ wi·(modeli − base)
with wi = 1/7 for all 7 checkpoints (Σwi = 1):
  = base + (1/7)·Σmodeli − (7·1/7)·base
  = base + avg(modeli) − base
  = avg(modeli)

Linear:  merged = Σ wi·modeli = avg(modeli)

The base terms cancel exactly. This is exactly why Linear and Task Arithmetic scored within noise of each other in our replication — not a coincidence, a mathematical identity. The two methods only diverge when weights don't sum to 1 (e.g. a single-checkpoint edit with weight ≠ 0.5), or when sparsification/sign-consensus is layered on top, as in TIES and DARE-TIES.

Conclusion

What the claim gets right, and what it misses

✗

Not confirmed: Task Arithmetic is not uniquely the fix

Plain Linear averaging performs equivalently to Task Arithmetic on the paper's own success metric (beats base model) — and by our math, that's expected, not surprising, whenever both methods are configured with weights summing to 1. A methods comparison that doesn't control for this weight-normalization detail will always find them indistinguishable, and any claimed advantage for Task Arithmetic should be checked against this identity before being treated as a property of the delta-vector approach itself.

✗

Also not confirmed: TIES/DARE-TIES aren't inherently unreliable either

Our first TIES/DARE-TIES run collapsed catastrophically — but retuning to the paper's own hyperparameters (10% density, λ=0.1, unnormalized) fixed it completely: both now beat the base model on both benchmarks. The "most methods fail in the wild" framing looks, in our replication, to be substantially a default-hyperparameter artifact — every method we tested succeeds once tuned to the settings the paper itself used.
